2. START THE LINQA API â€” POWERSHELL WINDOW 2

The phone uses the API for sign-in, session restoration, chats, profile photos, search and scheduled-call counts. Metro alone is not enough.

First check whether the API is already running:

If it succeeds, leave the existing API running and skip starting another copy. If it fails, run the following in a separate PowerShell window:

Set-Location -LiteralPath 'C:\Users\cj_wo\OneDrive - Bowie State\Desktop\linqa\server'

Keep this window open. Wait for "Server listening at http://127.0.0.1:8088". The configured database must be running, and server\.env must contain the existing development configuration.

This command intentionally does not use --watch. The watched API repeatedly restarted in the previous session. After changing server code, press Ctrl+C in this API window and run the same command again.

4. FORWARD THE PHONE PORTS â€” BACK IN WINDOW 1

& $linqaAdb -s 10.0.0.27:5555 shell am start -n com.linqa.mobile/.MainActivity

"Intent has been delivered to currently running top-most instance" means Android brought an existing Linqa activity forward; it is not an error. Check the actual screen on each phone to confirm that the app loaded.

7. RELOAD AFTER MOBILE SOURCE CHANGES

On a development build, open the React Native menu:

TROUBLESHOOTING

- LG connection refused: verify its current Wi-Fi IP. To re-enable port 5555, connect the LG by USB, identify its USB ID with "adb devices -l", run "adb -s <LG-USB-ID> tcpip 5555", then reconnect over Wi-Fi. Replace the placeholder with the actual device ID. Accept phone prompts.
- ADB hangs: first make sure no installation or file transfer is in progress. Run "& $linqaAdb kill-server", then "& $linqaAdb start-server", reconnect the LG and repeat step 4.
- Port already in use: check the existing service before starting another copy. Do not terminate unrelated processes.
- Blank/loading/error screen: verify both API and Metro, then port forwarding and bundle location. Inspect API/Metro terminal output.
- "Could not resume session" while API is healthy: sign in again if the session is revoked. Do not clear app storage or uninstall merely to relaunch; that can remove local keys and history.
