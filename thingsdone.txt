8. PRODUCTION READINESS ASSESSMENT (checked Oct 14, 2026)
=====================================================================
VERDICT: NOT READY FOR PRODUCTION OR A PUBLIC/STORE RELEASE.
Fit for: continued development and testing on your own phones. A small closed beta
would need the "Must fix" list below first. The repository's own document
(docs/INDUSTRIAL_READINESS.md) also says it "is not a production-readiness claim";
nothing I found contradicts that.

WHAT I CHECKED (results)
- Server tests: 1,411 passed. 5 test files cannot run on this PC (they need the
  production-style config, Docker/PostgreSQL, or a mobile-only setting). In one run
  3 more tests timed out because I had other jobs running; they pass alone (12/12).
- Server production dependency audit: 0 vulnerabilities.
- Web app: builds; 23 test files, 87 tests pass. (Bundle is large: over 500 kB.)
- Mobile: type-check passes. There is no automated test command for the app itself,
  so none of the screens built this session has an automated UI test.
- Mobile dependency audit: 26 advisories (23 high, 3 moderate, 0 critical). Mostly in
  build tools (Metro, Expo CLI) but includes react-native and expo themselves.
  (An earlier review counted 25 with 1 critical on Expo 52; the Expo 57 upgrade
  cleared the critical but not the highs.)
- Expo doctor (this is a gate in the mobile release workflow): FAILS 3 of 21 checks:
  7 Expo packages are patch versions behind; app.json settings are not synced with the
  checked-in android/ folder; webrtc and incall-manager are untested on the New
  Architecture. As it stands the release workflow would fail at this step.
- Live use: ran on two real phones against the local server; most features above work.

MUST FIX BEFORE ANY REAL USERS (blockers)
1. Release signing key exposed. The keystore passwords were committed in cleartext
   (commit 77fcf52) and that commit is still on the pushed branch. Treat the key as
   compromised: rotate the passwords / make a new key, and have the repository owner
   check who has access. Removing the file later did not remove it from history.
2. The app is a debug build. It loads its code from Metro on this PC (that is why the
   debug warning bar shows), the APK is about 470 MB, and it is signed with the debug
   key. No release build (minified, release-signed) has been made or tested.
3. The server is in development mode. NODE_ENV=development, debug logging, a shared
   test secret for tokens, calling relay (TURN) pointing at a home-network address,
   browser access allowed only for localhost. Production mode needs real signing keys
   and extra secrets (the server refuses to start without them); that path has not
   been exercised.
4. No real providers connected. Sign-in codes are printed by the dev server instead of
   sent by SMS (no Twilio), there are no push notifications (no APNs/FCM keys), no
   cloud storage with encryption keys for media/vault (local disk is used), and no
   monitoring. Without push, an incoming call or message is missed whenever the app is
   closed. The "ready to join" banner also only works while the app is open.
5. Security review is incomplete. About 448 server routes were counted but not each
   reviewed for access control; no penetration test, no independent review of the
   encryption design, no live cross-account testing. The messaging layer (MLS) is
   intentionally set to fail closed, and on the Galaxy the "Verify safety number"
   screen said the number is not available, so users cannot yet verify who they are
   talking to. Treat "End-to-end encrypted" labels as unproven until that is closed.
6. Protected "view once" photos are unproven. Server rules and storage exist, but the
   real test is still undone: send a view-once photo phone to phone and try a
   screenshot and a screen recording. The database test suite for it could not run
   here (Docker error), and one planned piece (sender notifications hook) is missing.
7. Nothing has been through the project's own gates. The branch is 54 commits and
   about 1,800 files ahead of main, never reviewed or merged, and I could not see the
   result of the GitHub CI runs. The G0-G5 release gates need evidence and sign-offs
   that have not been produced.
8. iOS has never been built or run. Calling, photos, secure storage and the secure core
   are unproven there.

SHOULD FIX BEFORE A BETA
- After every app restart, for about 40 seconds chats show "Encrypted message" and
  calls cannot start while the secure session unlocks. Needs a visible "securing..."
  state or a faster unlock.
- Two people pressing Join at the very same second can still ring each other.
- Group scheduled calls need an exact-match group chat; there is no join screen for a
  scheduled call itself (Join places an ordinary call).
- Version number: now 1.3.0 everywhere (menu, app.json, package.json, Android versionName and
  runtime version). Android versionCode is still 2; raise it before the next release build.
  The menu number is still typed in by hand (drawerItems.ts), so it can drift again.
- Over-the-air updates are configured (Expo updates, runtime 0.3.0, channels internal/
  beta/production) but have never been tried; decide how updates are signed and rolled
  back before relying on them.
- Database changes were not applied automatically on this PC (migration 070 was missing
  and broke message history earlier). Production needs the migration step enforced and
  a backup/restore drill (the ops/ runbooks exist but have not been exercised).
- The LG phone is an older Android and showed a drawing bug the Galaxy did not; test a
  wider set of devices. Android/iOS accessibility, low-memory and offline behaviour not
  tested.
- Many fake test accounts exist in the dev database; use a clean database for any beta.
- The yellow "Open debugger to view warnings" bar: warnings were never reviewed.
- Mobile dependency advisories (23 high) and the 7 Expo patch updates.

CAN WAIT
- Scheduler/ Vue prototype: it duplicates the app's scheduler and calls routes the real
  server does not have. Keep it out of any release, or move it to its own repository.
- Wording, spacing and other cosmetic items; remaining places that show an initial
  instead of a photo (none known after this session, but not every screen was checked).
