IMPLEMENTED
1. Production first-party sessions now use an Ed25519 PKCS#8/SPKI signing and
   verification pair. HS256 is development/test-only, and production config
   rejects missing or partial asymmetric key configuration.
2. Authentication challenge purposes are enforced. Recovery, identifier-add,
   and high-risk challenges cannot mint a generic authenticated session.
3. Pre-enrollment sessions are limited to profile:read and devices:read. Full
   write scopes are issued only after verified device enrollment.
4. OTP issuance is limited per identifier and per pseudonymized IP, delivery
   failures roll back the challenge, and IP hashes use a dedicated production
   secret instead of the JWT secret.
5. Refresh rotation preserves the real external subject. Expo now refreshes,
   serializes concurrent refresh attempts, stores both rotated tokens, and
   clears an expired session after refresh failure.
6. The mobile hub is authenticated and user-scoped in production. Expo and
   Android now use Bearer-authenticated /v1/mobile-hub HTTP and WebSocket
   routes; development-only demo routes remain unavailable in production.
7. Android identifier normalization no longer assumes the United States (+1).
8. CountryLinqa has authenticated post/event authoring routes and a real mobile
   composer. Production navigation no longer enters the static mock showcase.
9. CountryLinqa supports a deployment-owned, fail-closed HTTP GeoIP provider;
   readiness remains false when it is not configured.
10. Previously inert Calls and Privacy Center controls now navigate to real
    flows or invoke the real revocation service.
11. Web validation test typing was corrected, restoring the production build.
12. Route regression tests cover the production mobile hub and CountryLinqa
    authoring endpoints. Authentication policy tests cover EdDSA round-trip,
    challenge purpose isolation, and minimal pre-enrollment scopes.
