P0-1. Real client-to-client encrypted messaging path -- WEB 1:1 CLOSED

  Implemented evidence:
  - core/src/wasm.rs exposes the Rust identity, enrollment, key-package,
    encrypt, decrypt, replay, and runtime operations through a versioned ABI.
  - clients/web/public/linqa-core contains generated browser bindings and the
    release WASM artifact with secure browser randomness.
  - RawWasmCoreBridge persists wrapped device key material and invokes Rust for
    signed packages and hybrid X25519 + ML-KEM authenticated envelopes.
  - SecureDeviceEnrollment uses the same Rust key identity for the signed
    enrollment proof, device-bound session, and subsequent key publication.
  - Server key-package publication validates canonical Ed25519 signatures and
    enrolled-device identity; relay receive supplies the sender enrolled key.
  - SecureMessagingRuntime and ProductionMessagingCoordinator connect durable
    encrypted IndexedDB state, key directory, relay, decrypt, and acknowledge.
  - RawWasmCoreBridge.test.ts proves an Alice-to-Bob authenticated round trip.

  Remaining recommendation:
  Add the equivalent UniFFI/native mobile binding, multi-device/offline restart
  device-lab executions, and deployed WebSocket wake/relay acceptance evidence.

P0-2. General production phone/email authentication -- CODE CLOSED

  CompositeAuthDelivery now routes phone challenges to the configured Twilio
  provider and email challenges to HttpTransactionalEmailDelivery. Production
  fails closed when either channel is unconfigured; development may use the
  explicit console adapter. Provider credentials and sandbox/delivery evidence

  Provider-dependent attachment, push, billing, SMS, recovery-email,
  CountryLinqa encryption, and secure-core distribution capabilities now report

  consume them once; require fresh passkey/device proof; and centralize the guard
