Stack summary
  - Backend:   Node >= 22, Fastify 5, zod, pg, jose (JWT), ws, pino, @simplewebauthn,
               AWS SDK (KMS, S3). Package: @linqa/server (ESM, tsx for dev, vitest).
  - Mobile:    Expo SDK 57, expo-router, React Native, expo-secure-store,
               expo-local-authentication, WebRTC, SQLite outbox. Package: linqa-mobile 1.3.0.
  - Web:       Vite + React + TypeScript.
  - Desktop:   Tauri (Rust shell) + Vite/TS.
  - Core:      Rust crate (Cargo) with UniFFI + WASM bindings.
  - Deploy:    Docker (server/Dockerfile), k8s/api-deployment.yaml, Terraform, GitHub Actions
               (GHCR image publish, signed releases, SBOM).

6. DATA FLOW (MESSAGING PATH)
--------------------------------------------------------------------------------
  Mobile UI (app/, components/)
    -> services/conversation-engine + conversation-gate (key-protection gate: only
       OS-protected / hardware-backed keys, or native SecureStore adapter, may send)
    -> src/core/SecureCore.ts -> Rust core (seal / MLS / envelope)
    -> src/messaging/sqlite-outbox (durable encrypted offline outbox, metadata protected)
    -> HTTPS: server/src/routes + chat/chat-v2.routes  (auth: JWT header, scopes
       messages:send, device ownership, rate limit, zod validation)
    -> services/delivery + chat-outbox + Redis bus (chat-redis-bus) + Postgres
    -> Realtime: server/src/realtime/hub.ts (WebSocket; messages:read scope, revoked
       devices excluded) -> recipient client chat-realtime.client
    -> push (services/push*, push-providers) for offline devices
  Attachments: client seals file -> routes/attachments -> storage/S3 + CDN;
       membership-based sharing; plaintext metadata rejected.
